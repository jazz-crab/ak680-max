# Регламент прошивки (Windows)

Документ описывает **как безопасно записывать конфигурацию в AJAZZ AK680 MAX**
и что делать, если запись не подтвердилась. Пока только Windows — на ней
проверяется протокол и поведение прошивки v306.

---

## 1. Термины

- **Прошивка (в этом репозитории)** — запись пользовательского профиля в
  энергонезависимую память клавиатуры через HID feature reports. Это **не**
  обновление прошивки микроконтроллера и **не** перепрошивка загрузчика.
- **Устройство** — AJAZZ AK680 MAX, VID:PID `3151:502D`, конфигурационный
  интерфейс HID: usage page `0xFFFF`, usage `0x02`.
- **Конфиг** — `config/default.toml`, источник истины.
- **Бэкап** — JSON-снимок состояния, снятый командой `ak680 backup`.

## 2. Что делает `apply` и чего он не делает

`ak680 apply --yes` пишет:

1. base-layer keymatrix (позиция → HID usage);
2. Fn-слой для Windows (`fn_win`);
3. порог активации и отпускания Hall Effect для всех 90 позиций;
4. userpic (per-key подсветка) в слот и параметры LED-режима.

`apply` **не**:

- не обновляет прошивку MCU;
- не вызывает `CMD_SET_RESET` (`0x01`) — команда объявлена в протоколе, но
  код её не использует;
- не меняет профили 1–3, если в конфиге `profile = "active"` и активен профиль 0;
- не настраивает макросы, tap-hold и сценарии, которых нет в конфиге.

Настройки хранятся в памяти клавиатуры: после записи вендорский софт не нужен,
переподключение и перезагрузка их не сбрасывают.

## 3. Поддерживаемая среда

| Параметр | Требование |
|---|---|
| ОС | Windows 10/11 x64 |
| Python | 3.11+ |
| Зависимости | `hidapi`, `Pillow` (ставятся из `pyproject.toml`) |
| Подключение | проводное, желательно прямой порт сзади системного блока |
| Прошивка | v306 (`precision = 100`) |
| Права | обычный пользователь, администратор не нужен |

Не используй RDP/USB-over-IP, виртуальные машины с пробросом USB и
некачественные хабы: запись идёт короткими feature-репортами, потери и
задержки там не диагностируются.

## 4. Идентификация устройства

Перед первой записью:

```powershell
py -3 -m pip install -e .
ak680 status
```

Ожидаемо:

```
device_id=2255 firmware=v306 profile=0
  keymatrix layer0: ...
  ...
```

Проверить, что Windows видит именно клавиатуру:

```powershell
Get-PnpDevice -PresentOnly |
  Where-Object InstanceId -like '*VID_3151&PID_502D*' |
  Select-Object FriendlyName, Class, InstanceId
```

Должен быть `USB Composite Device` и HID-интерфейсы, среди них — vendor-defined
(`usage_page 0xFFFF`). Если устройства нет — проверь кабель, порт и режим
переключателя на корпусе.

## 5. Чеклист перед записью

Выполнять по порядку. Если пункт не выполняется — **не писать**.

- [ ] Клавиатура подключена проводом, не через hub/VM/RDP.
- [ ] Вендорская утилита AJAZZ и любые её фоновые процессы закрыты.
- [ ] `git status` чистый или изменения конфига осознаны.
- [ ] `ak680 status` показывает `v306` и ожидаемый профиль.
- [ ] `ak680 backup` выполнен, путь к JSON записан.
- [ ] `ak680 apply` (без `--yes`) показывает правильный план.
- [ ] Питание стабильно; спящий режим/гибернация на время записи отключены.
- [ ] Кабель не будет задет: запись идёт несколько секунд.

## 6. Бэкап

```powershell
ak680 backup
```

Файл: `backups/backup-YYYYMMDD-HHMMSS.json`. Внутри:

- `profile`, `info` (device_id, версия прошивки);
- `keymatrix.layer0..layer3` — по 90 четырёхбайтовых записей;
- `fn_win` — Fn-слой для Windows;
- `led` — параметры LED (эхо-байт + 7 параметров);
- `actuation_raw`, `release_raw` — по 90 значений;
- `mode_raw` — режим магнитов;
- `userpic_slot0` — 378 байт подсветки.

Правила:

- бэкап делается **до каждой** записи; `apply --yes` делает его автоматически;
- `backups/` не коммитится (`.gitignore`);
- бэкап — это снимок профиля, а не дамп прошивки MCU;
- `restore` — best-effort: восстанавливает keymatrix, Fn(Win), магниты,
  userpic и LED-параметры; `mode_raw` и профили 1–3 не восстанавливает.

## 7. Порядок записи

`apply --yes` пишет строго в этом порядке:

1. **Base-layer** — по одной позиции, каждая с read-back.
2. **Fn(Win)** — по одной позиции, каждая с read-back.
3. **Hall Effect** — массив активации, затем массив отпускания.
4. **Подсветка** — userpic, затем LED-параметры.
5. **Проверка** — повторное чтение и сравнение с конфигом.

Почему так:

- прошивка иногда «глотает» подряд идущие записи keymatrix, поэтому каждая
  запись подтверждается чтением (до 8 попыток, пауза 0.15 с);
- массивы магнитов пишутся страницами по 56 байт; последняя страница — с
  задержкой 0.25 с;
- userpic — 378 байт, 7 страниц по 56 байт; LED-команда использует вариант
  checksum `bit8`;
- итоговая проверка читает устройство заново, а не доверяет ответам записи.

## 8. Нормативные правила

**MUST**

1. Перед первой записью на новой машине — `status` + `backup`.
2. Перед каждой записью — dry-run `ak680 apply`.
3. Во время записи не запускать вендорскую утилиту и не писать из двух
   процессов одновременно.
4. Не выдёргивать кабель до строки `Готово.` / `ЕСТЬ ПРОБЛЕМЫ`.
5. После записи — `ak680 verify`; код возврата `0` обязателен.
6. Не коммитить `backups/`, `logs/`, `preview/`.
7. Не менять `precision` без проверки версии прошивки через `status`.

**MUST NOT**

1. Не вызывать `CMD_SET_RESET` (`0x01`) и не добавлять «reset» в CLI.
2. Не писать в устройство с другой прошивкой, не обновив `firmware`/`precision`.
3. Не запускать `apply --yes` на заблокированном/спящем компьютере.
4. Не использовать `--no-backup` в обычной работе (только для отладки).
5. Не переносить `config/default.toml` на другое устройство без пересчёта
   матрицы и `channel_gain`.

**SHOULD**

1. Держать `profile = "active"` и менять только активный профиль.
2. После смены палитры сверять PNG-превью (`ak680 render`) с железом.
3. Хранить последние 3–5 бэкапов, остальные удалять вручную.

## 9. Windows-специфика

- **Драйвер не нужен.** Клавиатура использует стандартный HID-драйвер Windows;
  `hidapi` открывает vendor-интерфейс без замены драйвера.
- **Администратор не нужен.** Если `hidapi` не открывает путь, чаще всего
  виноват другой процесс (вендорская утилита) или USB-хаб, а не права.
- **Один писатель.** Закрой AJAZZ Software, AutoHotkey-скрипты, которые могут
  слать HID-отчёты, и вторые копии `ak680 apply`.
- **Порт.** Предпочитай порты на задней панели. Передний панельный разъём
  и дешёвый hub могут давать таймауты.
- **Сон.** Отключи сон/гибернацию на время записи; USB selective suspend не
  должен усыпить устройство между страницами userpic.
- **Кодировка.** Если в PowerShell кракозябры, выполни
  `$env:PYTHONUTF8 = "1"` и `chcp 65001`.
- **Антивирус** обычно не мешает: запись идёт в HID, а не в файловую систему.
- **Пути.** Запускай команды из корня репозитория, иначе `config/default.toml`
  не найдётся; либо передай `--config` / `AK680_CONFIG`.

## 10. Ошибки и восстановление

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `не найден конфигурационный HID-интерфейс` | кабель/порт/режим, устройство не подключено | переподключить, другой порт, проверить Device Manager |
| `Ошибка HID: ...` при открытии | интерфейс занят вендорской утилитой | закрыть её, переподключить клавиатуру |
| `НЕ ПОДТВЕРДИЛОСЬ` на одной позиции | прошивка проглотила запись | повторить `ak680 apply --yes`; проверить `verify` |
| `НЕ ПОДТВЕРДИЛОСЬ` на нескольких подряд | плохой контакт/хаб/питание | другой порт, прямой кабель, повторить |
| подсветка не та | не тот слот/режим, старая палитра | `ak680 render`, сверить палитру, `apply --yes` |
| клавиши работают не так | записан не тот профиль/раскладка | `status`, проверить `profile`, `base_remaps` |
| клавиатура «зависла» | сбой USB во время записи | отключить/подключить; настройки в памяти сохранятся |
| всё сломалось после экспериментов | неверный конфиг | `ak680 restore backups/<файл>.json --yes` |

Если клавиатура перестала определяться altogether: отключи её, подожди 10 с,
подключи в другой порт. Профиль хранится в NVM и не должен теряться. Если
устройство не возвращается — используй вендорскую утилиту/сброс к заводским
настройкам, затем `status` и `backup`.

## 11. Откат

Три уровня, от предпочтительного:

1. **Конфиг в git.** `git checkout <commit> -- config/default.toml`, затем
   `ak680 apply --yes`, `ak680 verify`. Это основной способ: история конфига
   и есть история настроек.
2. **Бэкап.** `ak680 restore backups/backup-....json --yes`. Восстанавливает
   keymatrix, Fn(Win), магниты, userpic и LED. Не восстанавливает профили 1–3
   и `mode_raw`.
3. **Вендорская утилита / заводской сброс.** Крайний случай, когда нужно
   вернуть заводское состояние целиком.

## 12. Обновление прошивки клавиатуры

Обновление MCU — отдельная операция, не в этом репозитории.

После обновления:

1. `ak680 status` — зафиксировать новую версию.
2. `ak680 backup` — снять состояние.
3. Сверить `precision`: для v306 это `100` (0.01 мм). Для другой версии
   проверить по `status`/документации и обновить `[switches].precision`.
4. Обновить `[device].firmware` в конфиге.
5. `ak680 apply` → `--yes` → `verify`.

Если версия неизвестна — **не писать**. Сначала read-only `status`/`backup`.

## 13. Перенос настроек на другое устройство

Этот репозиторий — про AK680 MAX. При смене клавиатуры:

1. Скопируй `config/default.toml` как черновик намерения.
2. Перенеси `base_remaps`/`fn_remaps`, но **пересчитай позиции матрицы** под
   новую плату (матрица — не физическая раскладка).
3. Пересчитай `actuation_mm`/`release_mm`/`precision` под новый контроллер.
4. Перекалибруй `channel_gain` и `levels` (см. `tools/calibrate_colors.py`).
5. Не копируй `userpic` и сырые байты: у другой платы другой порядок матрицы.
6. Сделай отдельный репозиторий/конфиг под новое устройство, а этот не ломай.

## 14. Что коммитить

Коммитить:

- `config/default.toml`;
- `src/`, `tools/`, `docs/`, `README.md`, `PROVISIONING.md`, `pyproject.toml`;
- `docs/preview.png` (если менял палитру).

Не коммитить:

- `backups/`, `logs/`, `preview/`, `__pycache__/`, `.venv/`.

## 15. Финальный чеклист

```powershell
ak680 status
ak680 backup
ak680 apply            # dry-run
ak680 apply --yes
ak680 verify           # должен вернуть 0
```

Ручная проверка после `verify`:

- [ ] `Caps` даёт `Esc`;
- [ ] угол даёт `` ` `` / `ё`;
- [ ] правый столбец: `Del`, `Home`, `PrtSc`, `End`;
- [ ] `Fn+T` даёт `` ` ``;
- [ ] все клавиши срабатывают примерно на 1.0 мм и отпускаются на 1.5 мм;
- [ ] подсветка совпадает с `docs/preview.png` по зонам.
